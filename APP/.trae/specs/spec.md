# 食库管家 —— 项目开发 Spec 文档

## 一、项目概述

### 1.1 项目目标
**食库管家**是一款面向家庭用户的食材进销存管理 + 智能配菜决策 AI Agent 应用。旨在帮助用户高效管理冰箱食材库存，减少食物浪费，同时基于现有食材智能推荐菜谱，提升家庭烹饪体验。

### 1.2 核心价值
- **减少浪费**：通过临期预警机制，提醒用户及时消费即将过期的食材
- **智能配菜**：基于现有库存自动生成适配菜谱，最大化利用已购食材
- **采购规划**：结合口味偏好生成一周膳食计划和精准采购清单
- **数据洞察**：提供采购支出、浪费分析等数据报表，辅助家庭饮食决策

### 1.3 目标用户
- 家庭主妇/主夫，日常负责食材采购和烹饪
- 关注饮食健康、追求营养均衡的年轻人群
- 需要管理家庭饮食预算、减少浪费的用户

## 三、技术选型建议

### 3.1 架构选型
- **前端框架**：Vue 3（Composition API，开发体验好）
- **UI组件库**：Vant 4（移动端优先，轻量美观）
- **状态管理**：Pinia（Vue官方推荐，轻量简洁）
- **本地存储**：LocalStorage（主数据）+ IndexedDB（图片存储）

### 3.2 技术栈
- **语言**：JavaScript（简洁高效，适合Demo快速开发）
- **构建工具**：Vite（极速开发服务器，快速构建）
- **路由**：Vue Router 4（单页应用路由管理）
- **图表库**：Chart.js（轻量图表库，支持饼图/柱状图/折线图）
- **AI接口**：调用大模型API（如OpenAI/文心一言/通义千问）

### 3.3 部署方案
- **开发模式**：Vite开发服务器，热更新调试
- **构建输出**：纯静态HTML/CSS/JS文件，可由任意静态服务器托管
- **单文件部署**：使用vite-plugin-singlefile打包为单个HTML文件，双击即可运行

### 3.4 关键设计决策

#### 3.4.1 数据存储策略
- **主数据存储**：食材库存、出入库流水使用LocalStorage，实时读写，数据量可控
- **图片存储**：食材照片使用IndexedDB，支持较大文件存储
- **数据备份**：每日自动生成库存快照，支持手动导出CSV/JSON

#### 3.4.2 状态管理设计
- **全局状态**：库存数据、流水日志、系统配置
- **局部状态**：页面表单数据、筛选条件、临时计算结果
- **响应式更新**：数据变更时自动触发相关组件重新渲染

#### 3.4.3 AI接口设计
- **接口协议**：HTTP/HTTPS REST API
- **请求格式**：JSON格式，包含食材列表、用户偏好等参数
- **响应格式**：结构化JSON，包含菜谱列表、缺料清单等
- **超时处理**：设置15秒超时，超时后提示用户重试

#### 3.4.4 容错机制设计
- **数据损坏恢复**：检测到数据异常时提供"恢复备份"或"重置数据"选项
- **离线降级**：核心功能完全离线可用，AI功能提示需联网
- **操作撤销**：出库操作后10秒内可撤销，支持库存回滚

## 五、核心设计决策

### 5.1 数据模型设计

| 字段名 | 类型 | 说明 | 必填 |
|:---|:---|:---|:---:|

| name | String | 食材名称 | 是 |
| category | String | 分类：蔬菜/肉禽蛋奶/水产/干货调料/速冻食品 | 是 |
| quantity | Number | 存量数量 | 是 |
| unit | String | 单位：个/斤/克/升等 | 是 |
| purchaseDate | String | 采购日期，YYYY-MM-DD | 是 |
| expiryDate | String | 保质期截止日期，YYYY-MM-DD | 是 |
| storageZone | String | 存放分区：冷藏室/冷冻层/常温 | 是 |
| price | Number | 采购单价（元） | 否 |

| photo | String | 照片Base64或IndexedDB存储路径 | 否 |
| status | String | 状态：正常/临期/过期/异常 | 是 |
| createdAt | String | 创建时间 | 是 |
| updatedAt | String | 更新时间 | 是 |

#### 5.1.2 出库流水表（outbound_log）

| 字段名 | 类型 | 说明 | 必填 |
|:---|:---|:---|:---:|

#### 5.1.3 用户偏好表（user_preference）

|:---|:---|:---|:---:|
| id | String | 唯一标识 | 是 |
| dietaryRestrictions | Array | 忌口食物列表 | 否 |

|:---|:---|:---|:---:|
| lastInspectionDate | String | 最后一次巡检日期 | 是 |
| backupSnapshot | String | 库存快照JSON | 否 |
| alertCount | Object | 当日各食材提醒次数统计 | 否 |

### 5.2 界面设计原则

#### 5.2.1 移动端优先
- 适配375px~430px宽度范围
- 核心按钮触控区域≥44×44px
- 字体大小≥14px

#### 5.2.2 操作流程简洁
- 核心任务（入库/出库/查菜谱）操作路径≤3步
- 表单自动填充减少用户输入
- 一键式操作优先

#### 5.2.3 视觉反馈明确
- 三色预警标签：绿色（安全）、黄色（警告）、红色（危险）
- 操作成功/失败即时Toast提示
- 异常状态醒目展示

### 5.3 业务规则设计

#### 5.3.1 临期判定规则
- **绿色**：剩余保质期 > 7天
- **黄色**：剩余保质期 3~7天
- **红色**：剩余保质期 ≤ 2天
- **已过期**：剩余保质期 < 0

#### 5.3.2 出库校验规则
- 消耗数量 > 库存数量：拦截并提示
- 库存为0的食材：禁止出库操作
- 批量出库：任一食材库存不足则整单回滚

#### 5.3.3 AI菜谱生成规则
- 有效食材 < 3种：返回"库存不足"提示
- 存在红色食材：优先推荐包含该食材的菜谱
- 生成超时 > 15秒：显示超时提示，允许重试

## 八、异常处理策略

| 场景 | 触发条件 | 系统响应 | 用户恢复路径 |
|:---|:---|:---|:---|
| 必填字段缺失 | 入库/出库提交时字段为空 | 前端实时标红，阻止提交 | 补填后重新提交 |
| 库存不足出库 | 消耗数量 > 当前余量 | 弹窗提示，按钮置灰 | 修改数量或入库补货 |
| 出库误操作 | 提交后10秒内反悔 | 顶部显示撤销Toast | 点击撤销回滚 |
| 食材已过期 | 剩余保质期 < 0 | 置顶标红，禁止用于AI菜谱 | 执行报废出库 |
| 照片上传失败 | 文件>5MB或格式不支持 | 提示压缩/更换格式，允许跳过 | 压缩重传或跳过 |
| AI生成超时 | 请求超过15秒 | 显示超时提示 | 点击重试 |
| 存储满 | LocalStorage超出配额 | 提示导出备份后清理 | 导出CSV后清理 |
| 数据损坏 | 本地存储解析异常 | 提供恢复备份或重置数据 | 选择恢复方案 |
| 系统日期异常 | 设备日期被回拨 | 以最后巡检日期为基准 | 校准日期后刷新 |
| 空库存查菜谱 | 有效食材 < 3种 | 返回库存不足提示 | 前往入库页 |
