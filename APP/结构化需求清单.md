# 食库管家 —— 结构化需求清单

> 项目：家庭冰箱食材进销存管理 + 智能配菜决策 AI Agent  
> 生成日期：2026-06-27  
> 目标：初赛 Demo 可演示版本

---

## 一、功能需求（按模块划分）

### 模块 1：食材台账管理模块（核心基础）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F1.1 | 手动标准化入库 | 用户填写食材名称、分类（蔬菜/肉禽蛋奶/水产/干货调料/速冻食品）、存量数量、采购日期、保质期、存放分区（冷藏室/冷冻层/常温），必填项校验通过后写入全局库存表 | P0 |
| F1.2 | 默认保质期自动填充 | 系统内置主流食材默认保质期数据库，用户选择食材分类+名称后自动填充建议保质期，支持用户手动修改 | P0 |
| F1.3 | 拍照辅助存档 | 允许用户上传食材外包装/购物小票照片作为凭证，照片仅关联存储，不参与任何图像识别解析 | P1 |
| F1.4 | 全局库存清单 | 以列表/卡片形式展示全部在库食材，支持按分类、存放分区筛选，支持按名称搜索，支持按保质期剩余天数排序 | P0 |
| F1.5 | 食材信息编辑 | 支持修改在库食材的存量、保质期、存放分区等字段，修改后实时刷新库存表 | P1 |
| F1.6 | 库存总量统计 | 首页展示当前在库食材总品类数、总件数、临期预警数 | P0 |

#### 异常流程

- **F1-E1 必填字段缺失**：用户提交入库时，如有必填项未填，前端实时标红提示，阻止提交，提示语精确到字段级别。
- **F1-E2 重复食材入库**：若系统中已存在同名同分类同分区的在库食材，弹出确认对话框，提示用户选择「合并库存（累加数量）」或「新建独立条目」。
- **F1-E3 保质期输入非法**：采购日期晚于当前日期，或保质期为 0/负数时，拦截提交并提示修正。
- **F1-E4 照片上传失败**：上传图片超过大小限制（如 5MB）或格式不支持时，提示用户压缩/更换格式，允许跳过照片直接完成入库。
- **F1-E5 库存数据异常**：存量数量出现负数时，系统自动标记该条目为异常状态，提示用户核对出库记录。

### 模块 2：出库消耗管理模块（进销存核心）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F2.1 | 烹饪消耗出库 | 用户在库存清单中勾选一个或多个食材，填写单次消耗数量，系统校验库存充足后自动扣减余量，支持批量提交 | P0 |
| F2.2 | 变质报废出库 | 用户选择报废食材，填写报废原因（下拉选项：过期变质/储存不当/其他），系统将该批次标记为浪费并扣减库存 | P0 |
| F2.3 | 存量清零出库 | 用户一键将某食材库存归零，弹出二次确认弹窗，确认后清空该食材全部余量 | P1 |
| F2.4 | 出库流水日志 | 每笔出库自动生成流水记录，包含：出库类型、食材信息、数量、时间、剩余库存，支持按时间范围/出库类型筛选查询 | P0 |
| F2.5 | 出库库存不足拦截 | 用户填写消耗数量大于当前库存时，系统拦截并提示「库存不足，当前余量为 X」 | P0 |

#### 异常流程

- **F2-E1 出库数量大于库存**：系统实时校验，若消耗量 > 余量，按钮置灰并弹出提示，禁止超额出库。
- **F2-E2 未选择食材即提交出库**：出库页面无任何食材被勾选时，提交按钮置灰，提示「请至少选择一项食材」。
- **F2-E3 批量出库部分失败**：多食材批量出库时，若其中一个食材库存不足，整单回滚，提示用户调整后重新提交（原子性操作）。
- **F2-E4 误操作撤销**：出库提交后 10 秒内提供「撤销」按钮，误触可一键恢复库存与流水。
- **F2-E5 报废食材已为零**：对库存已为 0 的食材执行报废出库时，提示「该食材已无库存，无需报废」。

### 模块 3：临期预警模块（风险决策）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F3.1 | 保质期自动核算 | 系统每日自动计算全部在库食材的剩余保质期天数 = 保质期截止日期 - 当前日期 | P0 |
| F3.2 | 三色分级标签 | 自动标记：绿色（剩余 >7 天）、黄色（剩余 3~7 天）、红色（剩余 ≤2 天），在库存列表中以色块/标签展示 | P0 |
| F3.3 | 临期推送提醒 | 黄色/红色等级食材进入系统时，主动在首页生成提醒卡片；红色等级触发弹窗级高优先级提醒 | P0 |
| F3.4 | 临期食材汇总页 | 独立页面一键汇总全部黄色+红色等级食材，按剩余天数升序排列，顶部显示总数 | P0 |
| F3.5 | 已过期食材标记 | 剩余保质期 <0 的食材自动标记为「已过期」，置顶展示并强烈提示立即处理 | P0 |

#### 异常流程

- **F3-E1 系统日期被篡改**：检测到用户设备日期异常回溯时，临期计算以最后一次正常巡检日期为基准，并提示用户校准系统时间。
- **F3-E2 保质期截止日期为空**：若某食材缺失保质期数据，无法计算剩余天数，标记为「数据不完整」并提醒用户补录。
- **F3-E3 提醒频繁打扰**：同一食材红色提醒每日最多弹窗 1 次，用户可手动标记「已处理」关闭当日提醒。

### 模块 4：AI 菜谱推荐模块（任务输出）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F4.1 | 实时库存读取 | AI 智能体自动读取当前在库全部食材清单作为输入 | P0 |
| F4.2 | 可用食材筛选 | 剔除库存为 0 或已过期食材，筛选出可用于烹饪的有效食材池 | P0 |
| F4.3 | 三档位菜谱生成 | 基于有效食材池，AI 生成三类菜谱：快手懒人餐（5-15分钟）、减脂轻食餐（低卡标注）、家常正餐硬菜 | P0 |
| F4.4 | 缺料清单标注 | 每道推荐菜谱自动标注所需缺失辅料，汇总为「缺材清单」，供用户参考采购 | P1 |
| F4.5 | 菜谱详情展示 | 展示菜名、预估烹饪时长、难度、所需食材清单（区分已有/缺失）、粗略热量、步骤概述 | P1 |
| F4.6 | 红色食材优先推荐 | 当系统存在红色等级食材时，AI 优先推荐包含该食材的菜谱，加速临期消耗 | P0 |

#### 异常流程

- **F4-E1 库存为空/极少**：当在库食材少于 3 种或全部过期时，AI 返回提示「库存不足，无法生成菜谱，请先采购入库」。
- **F4-E2 AI 生成超时/失败**：若 AI 推理超过 15 秒未返回结果，展示友好提示「菜谱生成中，请稍候…」，允许用户刷新重试或返回库存页。
- **F4-E3 生成菜谱与现有库存不匹配**：AI 推荐菜谱中包含非在库食材时，必须在「缺失辅料」中明确标出，禁止误导用户以为食材充足。
- **F4-E4 用户口味偏好缺失**：用户未录入口味偏好时，AI 按通用家常口味生成菜谱，不阻断功能使用。

### 模块 5：智能采购规划模块（长期规划）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F5.1 | 饮食偏好录入 | 用户录入家庭成员口味偏好（如：忌口、偏好菜系、辣度），支持修改 | P1 |
| F5.2 | 一周膳食规划 | AI 结合现有库存 + 口味偏好，自动生成未来 7 天每日三餐食谱 + 配套采购清单 | P1 |
| F5.3 | 采购清单去重 | 自动排除已充足库存食材，仅输出需补缺的食材及建议采购量 | P1 |
| F5.4 | 商超比价参考 | 针对采购清单中的食材，展示主流商超（如沃尔玛/永辉/盒马）的市场参考均价，标注性价比建议 | P2 |

#### 异常流程

- **F5-E1 用户未录入偏好**：允许直接生成通用版一周规划，口味偏好字段非必填。
- **F5-E2 比价数据缺失**：某食材无对应商超价格数据时，显示「暂无数据」占位，不阻断其他功能。
- **F5-E3 规划与库存变动冲突**：用户生成一周规划后，若期间食材被大量消耗/新增，提示「库存已变动，建议重新生成规划」。

### 模块 6：数据统计报表模块（数据洞察）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F6.1 | 月度采购支出统计 | 自动汇总当月全部入库食材的采购金额（用户录入时填写单价/总价） | P1 |
| F6.2 | 食材浪费分析 | 统计当月变质报废出库的总数量、总成本、浪费占比，以饼图/柱状图展示 | P1 |
| F6.3 | 高频菜式排行 | 基于用户消耗出库记录，统计当月高频使用的食材组合/菜式 Top5 | P2 |
| F6.4 | 浪费趋势对比 | 支持查看近 3 个月浪费金额/数量趋势折线图 | P2 |

#### 异常流程

- **F6-E1 用户未录入采购金额**：允许入库时不填金额，该条目不纳入支出统计，报表中标注「部分数据缺失」。
- **F6-E2 跨月数据为空**：新用户首月无历史数据时，报表页展示空状态插图与引导文案「记录一个月后即可查看分析」。

### 模块 7：系统管理模块（支撑层）

| 编号 | 功能点 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| F7.1 | 定时巡检逻辑 | 系统每日 08:00 自动遍历全部食材保质期，重新计算剩余天数并更新预警等级 | P0 |
| F7.2 | 数据本地持久化 | 所有数据存储于浏览器 LocalStorage/IndexedDB，刷新页面不丢失 | P0 |
| F7.3 | 数据导出 | 支持导出库存表、出入库流水为 CSV/JSON 格式，便于用户备份 | P2 |
| F7.4 | 数据初始化/清空 | 提供「重置所有数据」功能，二次确认后清空全部本地数据，恢复初始状态 | P2 |

#### 异常流程

- **F7-E1 浏览器存储空间不足**：LocalStorage 超过容量限制时，提示用户导出备份后清理历史流水数据。
- **F7-E2 数据损坏/解析失败**：检测到本地存储数据异常时，提供「恢复最近备份」或「重置数据」两个选项。
- **F7-E3 用户误触重置**：重置数据操作必须输入确认文字（如「确认删除」）并二次弹窗确认。

## 二、非功能需求

| 编号 | 类别 | 需求描述 | 优先级 |
|:---:|---|---|:---:|
| NF1 | 性能 | 页面首屏加载时间 ≤ 2 秒（本地运行，无网络依赖）；库存 100 条以内操作时响应 ≤ 300ms | P0 |
| NF2 | 可用性 | 界面操作路径不超过 3 步完成核心任务（入库/出库/查菜谱）；字体大小 ≥ 14px，按钮触控区域 ≥ 44×44px，适配中老年用户 | P0 |
| NF3 | 可靠性 | 数据操作具备原子性，出库扣减与流水记录必须同时成功或同时失败；每日自动备份库存快照 | P0 |
| NF4 | 兼容性 | 适配主流移动端浏览器（iOS Safari / Android Chrome / 微信内置浏览器），支持 iOS 12+ / Android 8+ | P0 |
| NF5 | 安全性 | 初赛阶段纯本地运行，无用户账号体系，不上传个人隐私数据至服务端；照片存储于本地 | P1 |
| NF6 | 可维护性 | 基于 TRAE Work 零代码搭建，业务逻辑通过结构化数据表 + 提示词配置实现，无需编写复杂后端代码 | P0 |
| NF7 | 可扩展性 | 数据表结构预留扩展字段（如营养成分、采购渠道），支持后续快速迭代多人共享、云端同步等功能 | P1 |
| NF8 | 离线可用性 | 核心功能（入库/出库/查询/预警）完全离线可用，AI 菜谱生成依赖大模型接口，需网络支持，失败时给出离线替代提示 | P0 |

## 三、边界约束（明确不做的范围）

| 编号 | 不做范围 | 说明 |
|:---:|---|---|
| B1 | ❌ AI 图像识别自动识别食材 | 彻底移除拍照识图功能，照片仅作凭证存档，从根源杜绝识别偏差问题 |
| B2 | ❌ 多用户/多家庭共享台账 | 初赛 Demo 为单用户本地使用，不实现家庭多人协作、权限分配、数据共享功能 |
| B3 | ❌ 在线支付 / 电商下单 / 外卖对接 | 仅生成采购清单与比价参考，不打通任何支付或交易平台 |
| B4 | ❌ 社交网络功能 | 不做邻里互动、食材互换、分享晒单等社交模块 |
| B5 | ❌ 实时云端同步与账号体系 | 初赛版本数据完全本地存储，不实现用户注册登录、云端备份、多设备同步 |
| B6 | ❌ 智能硬件 IoT 对接 | 不连接智能冰箱、温湿度传感器等硬件设备 |
| B7 | ❌ 专业级营养分析与膳食处方 | 仅提供粗略热量标注与通用口味适配，不做疾病饮食处方、过敏原深度追踪等专业医疗功能 |
| B8 | ❌ 复杂财务记账 | 仅统计食材采购支出与浪费成本，不做家庭全品类收支管理、预算编制、投资分析 |
| B9 | ❌ 菜谱视频/图文社区 UGC | AI 生成菜谱为系统输出，不支持用户上传原创菜谱、评论、点赞等社区功能 |
| B10 | ❌ 多语言国际化 | 初赛版本仅支持中文界面 |

## 四、验收标准

### 4.1 核心功能验收（必须通过）

| 验收项 | 验收标准 | 验证方式 |
|---|---|---|
| 食材入库 | 完整填写 6 个必填字段后提交，数据正确写入库存表，首页总量实时 +1 | 手动测试 10 条不同分类食材 |
| 烹饪出库 | 勾选 3 个食材批量出库，各扣减数量正确，库存余量 ≥0，流水日志生成 3 条记录 | 手动测试批量与单条场景 |
| 报废出库 | 选择报废原因后提交，该食材库存归零，月度浪费报表正确统计金额 | 测试后查看报表页数据 |
| 临期预警 | 手动修改某食材保质期为「今天+2天」，系统次日自动标记为红色并弹窗提醒 |  Mock 系统日期或等待自然日 |
| AI 菜谱生成 | 库存中有西红柿、鸡蛋、青椒时，AI 能生成至少 1 道包含上述食材的快手菜谱 | 现场演示输入输出 |
| 离线可用 | 断开网络后，入库/出库/查询/预警功能正常运行，仅 AI 菜谱按钮提示需联网 | 浏览器 DevTools 模拟断网 |

### 4.2 用户体验验收

| 验收项 | 验收标准 |
|---|---|
| 移动端适配 | iPhone SE（375px 宽）与 iPhone 14 Pro Max（430px 宽）上无横向滚动条，核心按钮可单手指触控 |
| 操作流程 | 从打开页面到完成一次入库 ≤ 30 秒（不含拍照时间）；完成一次出库 ≤ 20 秒 |
| 异常提示 | 所有异常场景均有中文友好提示，不使用技术错误代码（如 Error 500），禁止出现空白崩溃页 |

### 4.3 数据准确性验收

| 验收项 | 验收标准 |
|---|---|
| 库存一致性 | 执行任意 10 次出入库操作后，库存表中各食材余量 = 初始值 + 总入库 - 总出库，误差为 0 |
| 预警准确性 | 50 条测试数据中，三色预警等级判定准确率 100%，无漏标/错标 |
| 报表准确性 | 月度报表中的总支出 = 各入库金额之和；浪费金额 = 各报废出库金额之和 |

### 4.4 Demo 演示验收

| 验收项 | 验收标准 |
|---|---|
| 可独立运行 | 双击 HTML 文件即可在浏览器打开全部功能，无需安装额外软件/配置环境 |
| 演示数据 | 内置 15 条以上演示数据，覆盖全部食材分类与三色预警状态，展示时无需手动逐条录入 |
| 录屏完整性 | 演示视频覆盖：入库 → 库存查看 → 临期预警 → AI 菜谱 → 出库 → 报表，单视频时长 ≤ 5 分钟 |

## 五、异常流程汇总表（全局视角）

| 场景 | 触发条件 | 系统响应 | 用户恢复路径 |
|---|---|---|---|
| 必填字段缺失 | 入库/出库提交时字段为空 | 前端实时标红，阻止提交，滚动定位到首个空字段 | 补填后重新提交 |
| 库存不足出库 | 消耗数量 > 当前余量 | 弹窗提示「库存不足，当前余量 X」，按钮置灰 | 修改数量或先入库补货 |
| 出库误操作 | 用户提交后 10 秒内反悔 | 页面顶部显示「已出库 ✕ 撤销」Toast | 点击撤销，库存与流水回滚 |
| 食材已过期 | 剩余保质期 < 0 | 列表中置顶标红，首页强烈提示，禁止用于 AI 菜谱推荐 | 执行报废出库清理 |
| 照片上传失败 | 文件 >5MB 或格式不支持 | 提示「请上传 ≤5MB 的 JPG/PNG 图片」，允许跳过 | 压缩后重传或直接跳过 |
| AI 生成超时 | 菜谱请求超过 15 秒 | 显示加载动画，15 秒后提示「生成超时，请重试」 | 点击重试或返回重选食材 |
| 浏览器存储满 | LocalStorage 超出配额 | 弹窗提示「存储空间不足，请导出备份后清理」 | 导出 CSV 后清理历史数据 |
| 数据损坏 | 本地存储解析异常 | 进入「数据恢复模式」，提供「恢复备份」或「重置数据」 | 选择恢复方案 |
| 系统日期异常 | 设备日期被人为回拨 | 以最后一次正常巡检日期为基准计算保质期，提示校准时间 | 校准系统日期后刷新 |
| 空库存查菜谱 | 在库有效食材 < 3 种 | 返回提示「库存不足，请先采购入库」，并给出热门采购建议 | 前往入库页补充食材 |

## 六、权限边界

| 维度 | 初赛 Demo 定义 |
|---|---|
| **用户角色** | 仅支持单用户本地使用，无注册/登录/账号体系，无管理员/普通用户角色区分 |
| **数据归属** | 所有数据存储于当前设备浏览器本地，不同设备/浏览器之间数据完全隔离 |
| **操作权限** | 用户拥有全部功能的完整操作权限（增删改查），无需授权校验 |
| **照片访问** | 仅允许用户主动选择本地图片文件上传，不调用摄像头实时拍摄，不读取用户相册 |
| **AI 调用权限** | AI 菜谱生成调用大模型接口时，仅传递食材名称列表（无用户身份信息），返回内容仅限菜谱文本 |
| **数据导出权限** | 用户可随时导出属于自己的本地数据，格式为通用 CSV/JSON，无加密限制 |
| **数据删除权限** | 用户拥有彻底清空本地全部数据的权限，操作不可逆，需二次确认 |
| **外部系统权限** | 无对接第三方系统（支付/电商/社交/硬件）的权限与接口 |

---

*本清单为初赛 Demo 版本需求基线，复赛迭代时可基于边界约束外的扩展方向（如多人共享、云端同步、IoT 对接）进行升级。*
