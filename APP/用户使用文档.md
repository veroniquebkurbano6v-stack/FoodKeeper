## 一、产品简介

### 1.1 产品定位

**食库管家**是一款面向家庭场景的冰箱食材进销存管理 + 智能配菜决策 AI Agent 应用，致力于解决以下家庭厨房痛点：

- 食材过期浪费：买回来的食材忘记吃，发现时已过期
- 库存不清：不知道冰箱里还剩什么，重复采购
- 不知道做什么菜：面对一堆食材不知道如何搭配
- 采购无计划：缺什么记不住，到超市才想起

### 1.2 核心能力

| 能力模块 | 说明 |
|---------|------|
| 食材台账 | 录入、编辑、删除食材，支持分类、存放分区、采购日期、保质期管理 |
| 临期预警 | 三色分级（绿/黄/红/灰），自动核算剩余天数，已过期支持一键报废 |
| 出库管理 | 烹饪消耗、变质报废、存量清零三种出库方式，自动记录流水日志 |
| AI 菜谱推荐 | 接入 OpenAI / DeepSeek / 智谱清言 / Moonshot 大模型，根据冰箱库存智能推荐 5-6 道菜谱 |
| 采购计划 | 缺料清单生成，导出采购清单 |
| 数据报表 | 库存分布、本月支出、报废分析、近期出库记录 |
| 口味偏好 | 忌口、菜系、辣度偏好，影响 AI 菜谱推荐结果 |
| 用户管理 | 后端版支持多用户、角色权限、敏感字段脱敏 |

项目包含两套前端实现，共享同一份后端 API 设计：

## 二、运行模式选择

根据使用场景选择合适的运行模式：

| 模式 | 适用场景 | 数据存储 | 是否需要后端 | 启动复杂度 |
|------|---------|---------|-------------|-----------|
| **模式一：纯前端 Demo** | 个人试用、功能演示、移动端体验 | 浏览器 LocalStorage | 否 | ⭐ |
| **模式二：本地开发** | 二次开发、调试 | MySQL + Redis | 是 | ⭐⭐⭐ |
| **模式三：Docker 部署** | 个人/小团队生产使用 | MySQL + Redis | 是 | ⭐⭐ |
| **模式四：K8s 部署** | 企业级生产、高可用场景 | MySQL + Redis + PVC | 是 | ⭐⭐⭐⭐ |

> **新手推荐**：从「模式一」开始体验，无需任何后端配置，打开浏览器即可使用全部核心功能（AI 菜谱需自行配置 API Key）。

## 三、安装与部署

### 3.1 环境要求

**前端 A（Demo）**：
- Node.js 18+ 与 npm
- 现代浏览器（Chrome 90+ / Edge 90+ / Safari 14+ / Firefox 88+）

**前端 B + 后端**：
- Node.js 18+ 与 npm
- JDK 17
- Maven 3.9+
- MySQL 8.0
- Redis 7.x

**Docker 部署**：
- Docker 24+
- Docker Compose 2.20+

**K8s 部署**：
- Kubernetes 1.27+
- kubectl
- 私有镜像仓库 + imagePullSecret
- NFS StorageClass（用于 PVC）
- Ingress Controller（nginx-ingress）
- TLS 证书

### 3.2 模式一：纯前端 Demo 启动

```bash
# 1. 进入项目根目录
cd c:\Users\H1314\Desktop\TRAE食库管家\APP

# 2. 安装依赖
npm install

# 3. 启动开发服务器（默认端口 5173）
npm run dev

# 4. 浏览器访问
# http://127.0.0.1:5173
```

**构建单文件 HTML**（可双击直接打开，便于分发）：

```bash
npm run build
# 产物在 dist/index.html，单文件包含全部资源
```

**首次访问自动注入演示数据**：15 条食材（西红柿、鸡蛋、青椒、猪肉、土豆、牛奶、大米、速冻水饺、鱼、食用油、酸奶[已过期]、青菜、酱油、虾仁、洋葱），方便快速体验功能。

### 3.3 模式二：本地开发环境

#### 步骤 1：启动数据库中间件

```bash
docker-compose -f docker-compose.dev.yml up -d
# 启动 MySQL（容器 food-mysql-dev，端口 3306）和 Redis（容器 food-redis-dev，端口 6379）
```

#### 步骤 2：初始化数据库

```bash
# 使用 MySQL 客户端执行初始化脚本
mysql -h 127.0.0.1 -uroot -proot123 < scripts/init.sql

# 若需要使用「常用食品」功能，额外执行
mysql -h 127.0.0.1 -uroot -proot123 food_inventory < scripts/create_favorite_food.sql
```

#### 步骤 3：启动后端

```bash
cd backend

# 方式 A：IDE 运行
# 直接运行主类 com.food.FoodInventoryApplication，激活 dev profile

# 方式 B：Maven 命令行
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 或打包后运行
mvn clean package -DskipTests
java -jar target/food-inventory-manager.jar --spring.profiles.active=dev
```

后端启动后：
- 服务端口：`http://localhost:8080`
- 接口文档（Knife4j）：`http://localhost:8080/doc.html`
- 默认管理员账号：`admin / 123`

#### 步骤 4：启动前端 B

```bash
cd frontend
npm install
npm run dev
# 访问 http://localhost:5173，前端会自动代理 /api 到 8080
```

### 3.4 模式三：Docker 完整部署

#### 步骤 1：准备环境变量

```bash
cp .env.example .env
# 编辑 .env，务必修改以下项：
#   MYSQL_PASSWORD        数据库密码
#   MYSQL_ROOT_PASSWORD   数据库 root 密码
#   JASYPT_PASSWORD       配置加密密钥
#   IMAGE_PREFIX          镜像前缀（如 your-username/food-inventory）
```

#### 步骤 2：构建并启动

```bash
docker-compose up -d --build
```

#### 步骤 3：验证服务

```bash
# 查看容器状态
docker-compose ps

# 健康检查
curl http://localhost:8080/actuator/health   # 后端
curl http://localhost/health                  # 前端 Nginx

# 访问应用
# 前端：http://localhost
# 后端接口文档：http://localhost:8080/doc.html（生产 profile 默认禁用）
```

#### 端口与容器说明

| 服务 | 容器名 | 宿主机端口 | 容器端口 |
|------|--------|-----------|---------|
| MySQL | food-mysql | 3306 | 3306 |
| Redis | food-redis | 6379 | 6379 |
| Backend | food-backend | 8080 | 8080 |
| Frontend | food-frontend | 80 | 80 |

### 3.5 模式四：K8s 生产部署

详见 `k8s/README.md`，部署顺序：

```bash
kubectl apply -f k8s/namespace.yml
kubectl apply -f k8s/configmap.yml
kubectl apply -f k8s/secret.yml      # 必须先替换 base64 占位值
kubectl apply -f k8s/pvc.yml
kubectl apply -f k8s/service.yml
kubectl apply -f k8s/deployment.yml  # 注意：含 Helm 模板语法，需先处理
kubectl apply -f k8s/ingress.yml     # 需替换域名 + 配置 TLS
kubectl apply -f k8s/hpa.yml
```

**生产部署必做事项**：
1. 替换 `secret.yml` 中所有 base64 占位值为真实加密值
2. 替换 `ingress.yml` 中的域名 `*.example.com` 为真实域名
3. 配置 TLS 证书 Secret `food-inventory-tls`
4. 创建 `imagePullSecret` 名为 `regcred`
5. 确认 `deployment.yml` 的镜像仓库地址 `registry.example.com` 已替换
6. 配置 NFS StorageClass 或替换为可用的 storage-class
7. 部署 Prometheus + Grafana 监控
8. 部署 ELK / Loki 日志收集

## 四、移动端 Demo（前端 A）功能详解

> 适用于 `src/` 目录下的 Vant 4 移动端版本。所有数据存储在浏览器 LocalStorage，无需登录。

### 4.1 首页（Home）

进入应用首屏，自上而下依次为：

1. **顶部 Header 卡片**：渐变背景，显示「食库管家」品牌与 slogan「让食材管理更简单」
2. **我的菜谱入口**：橙金渐变卡片，显示已收藏菜谱数量，点击直达「我的菜谱」
3. **统计宫格**（2×2）：
   - 食材品类数
   - 库存总数量
   - 临期预警数（琥珀色高亮）
   - 已过期数（砖红色高亮）
4. **快捷入库按钮**：大号绿色按钮「新增食材入库」
5. **临期提醒区**：展示前 5 条临期/已过期食材卡片，右上角「查看全部」跳转临期预警页
6. **快捷操作宫格**（4×2）：库存管理、食材出库、AI 菜谱、数据报表、临期汇总、出库日志、口味偏好、系统设置

### 4.2 库存清单（Inventory）

**路径**：底部 Tab「库存」或首页「库存管理」

**功能**：
- **搜索**：按食材名称模糊搜索
- **分类筛选**：6 个 Tab（全部 / 蔬菜 / 肉禽蛋奶 / 水产 / 干货调料 / 速冻食品）
- **排序切换**：按保质期排序（临期优先）⇄ 按入库时间排序
- **食材卡片**：2 列网格展示，左侧分类色条，顶部状态点 + 剩余天数，中部食材名（18px 加粗），底部数量·分类
- **点击卡片**：跳转编辑页

**分类配色**：
| 分类 | 颜色 | 色值 |
|------|------|------|
| 蔬菜 | 鼠尾草绿 | #7c9473 |
| 肉禽蛋奶 | 暖玫瑰 | #c97b5c |
| 水产 | 雾霾蓝 | #6e8ca8 |
| 干货调料 | 暖驼棕 | #a67c52 |
| 速冻食品 | 冰灰蓝 | #6e8ca8 |

### 4.3 新增食材（AddFood）

**路径**：首页「新增食材入库」或库存页右上角「新增」

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 食材名称 | 文本 | ✅ | blur 时校验非空 |
| 分类 | 选择器 | ✅ | 5 个分类可选 |
| 数量 | 数字 | ✅ | 必须 > 0 |
| 单位 | 文本 | ✅ | 个/斤/克/升等 |
| 采购日期 | 日期选择器 | ✅ | 默认今天 |
| 保质期天数 | 数字 | ✅ | **根据食材名称+分类自动填充**（如选择蔬菜类输入「西红柿」自动填 7 天） |
| 保质期截止 | 只读 | — | 自动计算 = 采购日期 + 保质期天数 |
| 存放分区 | 选择器 | ✅ | 冷藏室 / 冷冻层 / 常温 |
| 单价（元） | 数字 | ❌ | 选填 |
| 总价（元） | 数字 | ❌ | 选填 |

**自动合并逻辑**：若已存在同名 + 同分类 + 同分区的食材，新增时会自动累加数量与总价，避免重复记录。

**提交成功**：显示「入库成功」Toast，1.5 秒后跳转库存页。

### 4.4 编辑食材（EditFood）

**路径**：库存页或临期页点击食材卡片

**与新增的区别**：
- 不能修改采购日期和保质期天数
- 直接编辑「保质期截止」日期
- 底部多一个红色「删除食材」按钮（需二次确认）

### 4.5 临期预警（Expiring）

**路径**：首页「临期汇总」或临期提醒区「查看全部」

**三色分级**：

| 状态 | 颜色 | 剩余天数 | 视觉表现 |
|------|------|---------|---------|
| 正常（fresh） | 绿色 | > 7 天 | 绿色状态点 |
| 临期（yellow） | 琥珀色 | 3-7 天 | 琥珀状态点 |
| 即将过期（red） | 砖红色 | 0-2 天 | 砖红状态点 + 呼吸动画 |
| 已过期（expired） | 暖灰色 | < 0 天 | 暖灰状态点 |

**统计栏**：3 列彩色卡片显示「即将过期 / 临期 / 已过期」数量

**分类 Tab**：全部 / 即将过期 / 已过期

**已过期处理**：每张已过期卡片底部带「报废处理」按钮，点击确认后调用变质报废流程。

### 4.6 食材出库（Outbound）

**路径**：首页「食材出库」

**三种出库方式**：

#### ① 烹饪消耗（cook）
- 列出所有 quantity > 0 的食材
- 勾选要消耗的食材，使用步进器设置消耗数量
- 底部显示「已选择 X 项」
- 点击「确认消耗」批量扣减
- **库存不足自动校验回滚**：任一食材库存不足时整个批量操作回滚

#### ② 变质报废（discard）
- 仅展示临期 / 已过期食材
- 每行右侧「报废」按钮
- 选择报废原因：过期变质 / 储存不当 / 其他
- 数量置 0，记录报废日志

#### ③ 存量清零（clear）
- 列出所有食材
- 每行「清零」按钮，二次确认后数量置 0

### 4.7 AI 菜谱推荐（Recipes）

详见 [第六章 AI 菜谱推荐使用指南](#六ai-菜谱推荐使用指南)。

### 4.8 采购计划（ShoppingPlan）

**路径**：首页无直接入口，通过 URL `/shopping-plan` 访问

**功能**：
- **缺料清单**：展示当前缺料食材（当前为 Mock 数据）
- **生成清单**：勾选缺料项转为采购清单
- **采购清单**：每项可标记「已买」移除，支持「清空」
- **导出清单**：复制到剪贴板

> ⚠️ 当前版本缺料数据为硬编码 Mock，未与 AI 菜谱的「需购买食材」联动，后续版本会改进。

### 4.9 数据报表（Reports）

**路径**：底部 Tab「报表」

**展示内容**：
- **统计卡片**（2×2）：库存总量、临期预警、本月报废、食材品类
- **分类库存分布**：横向条形图，5 个分类各显示品类数与百分比
- **库存明细**：前 10 条食材卡片网格
- **近期出库记录**：前 5 条日志，显示食材名、出库类型、减少量、日期

### 4.10 出库日志（Logs）

**路径**：首页「出库日志」

**筛选 Tab**：全部 / 烹饪消耗 / 变质报废 / 存量清零

**日志卡片**：
- 左侧类型色条（cook=绿 / discard=红 / clear=琥珀）
- 类型图标 + 中文标签 + 日期
- 食材名 + 减少数量
- 报废原因（如有）+ 剩余库存

### 4.11 口味偏好（Preferences）

**路径**：首页「口味偏好」或菜谱页「口味偏好」按钮

**字段**：
| 字段 | 说明 | 示例 |
|------|------|------|
| 忌口食物 | 逗号分隔 | 香菜,内脏 |
| 偏好菜系 | 逗号分隔 | 川菜,粤菜 |
| 辣度偏好 | 选择器 | 不限 / 不辣 / 微辣 / 中辣 / 特辣 |

**作用**：保存后注入 AI 菜谱生成 Prompt，影响推荐结果。

### 4.12 系统设置（Settings）

**路径**：首页「系统设置」

**功能分组**：

#### 数据管理
- **备份数据**：触发 LocalStorage 写入
- **恢复数据**：从 LocalStorage 重新读取
- **导出 JSON**：下载 `food-inventory.json`，含 foods / logs / preferences / exportTime
- **导出 CSV**：下载 `food-inventory.csv`，表头：名称/分类/数量/单位/采购日期/保质期截止/存放分区/单价/总价
- **重置数据**：确认后恢复 15 条演示数据，清空日志和偏好

#### 关于
- **关于应用**：显示版本号 v1.0.0 与说明文案
- **隐私设置**：纯展示，提示数据存储在本地

## 五、标准版（前端 B + 后端）功能详解

> 适用于 `frontend/` 目录下的 Element Plus 版本，对接 Spring Boot 后端。

### 5.1 用户认证

#### 登录
- **路径**：`/login`
- **账号**：默认 `admin / 123`（开发模式快捷登录）
- **流程**：输入用户名密码 → 后端校验 → 生成 Token 存入内存 → 前端存入 Pinia + localStorage → 跳转首页
- **Token 失效**：响应 code=3000/3002 时自动跳转登录页

#### 注册
- **路径**：`/register`
- **字段**：用户名（4-20 字符，仅字母数字下划线）、密码（1-32 字符）、昵称、手机号、邮箱

#### 登出
- 调用 `/api/auth/logout`，清空前端 Token

### 5.2 食材管理

调用后端 `/api/food/*` 接口：

| 操作 | 接口 | 说明 |
|------|------|------|
| 添加食材 | `POST /api/food/add` | 校验分类存在，自动计算保质期截止 |
| 快速添加 | `POST /api/food/quick-add` | 从常用食品一键添加，自动填充保质期和单价 |
| 修改食材 | `PUT /api/food/update` | 仅更新非空字段 |
| 删除食材 | `DELETE /api/food/delete/{id}` | 逻辑删除（deleted=1） |
| 食材详情 | `GET /api/food/detail/{id}` | 返回详情 VO，含剩余天数和状态 |
| 分页列表 | `GET /api/food/list` | 支持分类筛选、关键词搜索、分页 |
| 临期列表 | `GET /api/food/expiring?days=7` | 查询即将过期食材 |
| 食材出库 | `POST /api/food/outbound/{id}?quantity=N` | 减少库存，校验库存充足 |

### 5.3 常用食品管理

调用后端 `/api/favorite/*` 接口：

## 六、AI 菜谱推荐使用指南

### 6.1 功能概述

AI 菜谱推荐根据冰箱当前库存（含临期优先级）和用户口味偏好，调用大语言模型生成 5-6 道定制菜谱，每道菜谱包含：
- 菜名、烹饪时长、难度、热量估算
- 冰箱已有食材清单（按临期紧急程度着色）
- 需额外购买食材清单（含估价）
- 详细制作步骤（零基础版，含火候时间判断标准）
- 小贴士

### 6.2 支持 AI 服务商

| 服务商 | 模型 | 推荐 | API Key 获取地址 |
|--------|------|------|-----------------|
| OpenAI | gpt-4o-mini | ⭐⭐ | platform.openai.com |
| **DeepSeek** | deepseek-chat | ⭐⭐⭐⭐⭐（推荐） | platform.deepseek.com/api_keys |
| 智谱清言 | glm-4-flash | ⭐⭐⭐⭐（有免费额度） | open.bigmodel.cn |
| Moonshot | moonshot-v1-8k | ⭐⭐⭐ | platform.moonshot.cn |

### 6.3 配置步骤

1. **进入菜谱页**：底部 Tab「菜谱」或首页「AI 菜谱」
2. **打开 AI 设置**：点击页面右上角「AI 设置」文字按钮
3. **选择服务商**：推荐 DeepSeek 或智谱清言
4. **输入 API Key**：
   - OpenAI / DeepSeek / Moonshot：需 `sk-` 开头且 ≥ 20 字符
   - 智谱：≥ 10 字符
   - 输入框右侧眼睛图标可切换显隐
   - 实时格式校验，格式错误会显示红色提示
5. **（可选）自定义端点**：用于规避 CORS 限制，填自建代理地址
6. **测试连接**：点击「测试连接」按钮，发起轻量请求（max_tokens=5，超时 15 秒）验证 Key 有效性
7. **保存配置**：点击「保存配置」，Key 存入浏览器 localStorage，不会上传服务器
8. **清除 Key**：点击「清除已保存的 Key」可删除本地存储的 Key

### 6.4 生成菜谱

1. **前置条件**：库存中可用食材（quantity > 0 且未过期）≥ 3 种
2. **点击「生成菜谱」**：
   - 系统自动按剩余天数升序排列食材
   - 剩余 ≤ 2 天的食材标记【紧急消耗】
   - 剩余 ≤ 7 天的食材标记【临期】
   - 注入用户口味偏好（忌口 / 菜系 / 辣度）
   - 注入默认厨房佐料清单（油盐酱醋等）
   - 调用大模型生成 5-6 道菜谱
3. **等待过程**：
   - 显示加载动画 + 「AI 正在为您定制菜谱...」
   - 显示已等待秒数计时器
   - 可点击「取消」中断请求
   - 通常耗时 20-40 秒（请耐心等待）
4. **生成成功**：菜谱列表展示，可查看详情、收藏

### 6.5 菜谱分类

生成的菜谱自动分类到 5 个 Tab：

| Tab | 分类标准 | 典型菜谱 |
|-----|---------|---------|
| 全部 | 所有 AI 生成菜谱 | — |
| 快手懒人餐 | 烹饪时长 ≤ 15 分钟 | 凉拌黄瓜、番茄炒蛋 |
| 减脂轻食餐 | 热量 ≤ 250 kcal | 清炒时蔬、水煮鸡胸 |
| 家常正餐 | 其余 | 土豆炖鸡块、青椒炒肉 |
| 我的菜谱 | 用户收藏的菜谱 | 自定义 |

### 6.6 菜谱详情

点击菜谱卡片或「📝 X 步 · 点击查看详细做法」打开详情弹层（85% 高度）：

- **元信息**：时长 / 热量 / 难度
- **冰箱已有食材**：列表展示，含临期图标和颜色提示
- **需额外购买**：列表展示，含估价
- **详细制作步骤**：编号圆圈 + 步骤文本，零基础友好
- **小贴士**：烹饪技巧和安全提醒
- **底部操作**：
  - 未收藏 →「添加到我的菜谱」
  - 已收藏 →「已收藏 · 点击移除」

### 6.7 降级预案

当 AI 请求失败时（未配置 Key / 超时 / CORS / 401 / 429 / 5xx），系统自动返回 5 道本地经典菜谱：
- 西红柿炒鸡蛋
- 青椒炒猪肉
- 土豆炖鸡块
- 清炒时蔬
- 凉拌黄瓜

顶部会显示黄色降级提示条，告知用户当前显示的是本地菜谱。

### 6.8 缓存机制

- 生成成功的菜谱会缓存到 localStorage（key：`recipeAi.cache`）
- 下次进入页面显示「上次生成：X 分钟前」
- 点击「重新生成菜谱」可刷新缓存

### 6.9 收藏管理

- 收藏菜谱存入 localStorage（key：`recipeFavorites`）
- 基于菜谱签名（name::type）去重
- 首页「我的菜谱」入口卡片显示收藏数量，点击直达「我的菜谱」Tab

### 6.10 CORS 限制说明

由于浏览器安全策略，直接调用 OpenAI / 智谱 / Moonshot 接口存在 CORS 限制：

| 场景 | 解决方案 |
|------|---------|
| **开发环境（npm run dev）** | 自动通过 Vite 代理 `/ai-proxy/<provider>/*` 规避 |
| **生产单文件 HTML** | DeepSeek 原生支持 CORS 可直连；OpenAI / 智谱 / Moonshot 需在「AI 设置」中填自建代理端点 |
| **自定义代理** | 在「自定义端点」字段填入代理 URL，请求会优先走该地址 |

## 八、常见问题（FAQ）

### Q1：移动端 Demo 启动后白屏？

**排查步骤**：
1. 检查 Node.js 版本（需 18+）
2. 删除 `node_modules` 重新 `npm install`
3. 打开浏览器控制台查看报错
4. 确认 `vite.config.js` 中 `host` 配置为 `127.0.0.1`

### Q2：后端启动报「无法连接数据库」？

**排查步骤**：
1. 确认 MySQL 已启动：`docker-compose -f docker-compose.dev.yml ps`
2. 确认 `application-dev.yml` 中数据库配置正确（默认 localhost:3306，root/123456）
3. 确认已执行 `scripts/init.sql` 创建库表
4. 检查防火墙是否放行 3306 端口

### Q3：登录提示「用户名或密码错误」？

- 默认账号：`admin / 123`
- 若忘记密码，可重启后端，`DataInitializer` 会自动重置 admin 密码为 123
- 或直接执行 SQL：`UPDATE sys_user SET password='$2a$10$xxxxxx' WHERE username='admin';`（需用 BCrypt 生成新密码哈希）

### Q4：AI 菜谱生成失败，自动显示本地菜谱？

**常见原因**：
1. **未配置 API Key**：先在「AI 设置」中配置
2. **Key 格式错误**：检查是否符合前缀和长度要求
3. **CORS 限制**：生产环境需填自定义代理端点，或使用 DeepSeek（支持 CORS）
4. **请求超时**：5-6 道菜谱生成需 20-40 秒，请耐心等待
5. **额度耗尽**：检查服务商控制台余额
6. **max_tokens 过小**：系统已设为 4096，请勿手动调小

### Q5：常用食品功能报错 `NoResourceFoundException`？

**根因**：`favorite_food` 表未创建或后端未重新编译。

**解决方案**：
1. 执行 `scripts/create_favorite_food.sql` 创建表
2. 重新编译后端：`mvn clean package -DskipTests`
3. 重启后端服务
4. 详见 `docs/常用食品功能修复方案.md`

### Q6：移动端 Demo 数据丢失？

**原因**：LocalStorage 会被浏览器清除。

**预防**：
- 定期在「设置 → 导出数据」备份 JSON
- 不要使用浏览器「无痕模式」
- 不要手动清除浏览器缓存

### Q7：K8s 部署 `kubectl apply -f deployment.yml` 报错？

**根因**：`deployment.yml` 含 Helm 模板语法 `{{ include ... }}`。

**解决方案**：
1. 使用 Helm 部署：将文件转为 Helm Chart
2. 或手动替换所有 `{{ ... }}` 占位为实际值后 apply

### Q8：生产环境端口冲突？

- `application-prod.yml` 后端端口为 **8082**
- `docker-compose.yml` 暴露 **8080**
- 如需修改，编辑对应配置文件
